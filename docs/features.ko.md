# 기능

항목 상태는 `[ ]` 대기, `[~]` 진행, `[o]` 완료, `[!]` 보류, `[-]` 종료다.
- [o] A1 — P1: Manifest `plugin.json`이 식별자 `agents`, 이름, 설명과 두 section `agents.running`, `agents.definitions`를 각각 page(A3, A4)를 가진 view section으로 선언한다. `test/manifest-shape.test.mjs`가 그 선언을 core plugin spec의 manifest 규칙과 대조한다.
- [!] A2 — P1: 에이전트 CLI 계정을 settings로 선언한다. 보류: 계정이 아직 settings로 선언되지 않았다. 원인: core plugin spec의 settings 선언은 setting마다 scalar 값 하나(enum, 정수 범위, 문자열, address)만 담고, 계정 목록을 담는 선언이 없다. 재개 조건: plugin 소유자가 계정을 core settings 형식으로 둘지, plugin의 project data(`data`)에 든 목록으로 둘지 정하면 이 항목을 재개한다.
- [~] A3 — P1: 실행 중인 에이전트 section `agents.running`은 창의 agent tab을 `core.grid`의 group, card, tab tree로 보여 준다. 어느 plugin의 tab이든 `params.program`이 설정되면 agent tab이며, 이름은 `params.role`, 없으면 `params.program`이다. 각 tab의 활동은 `core.activity`에서 온다. 행을 누르면 `agents.running.select {tab}`이 실행되고, 이것은 `core.layout.select`를 실행한다. Tree 규칙은 `ui/running.js`에 있다(A11이 plugin 이름을 규칙에서 뺐다). Page는 `ui/running.html`과 `ui/running-view.js`다. 남은 부분: 행마다 program 상태(`idle`, `working`, `blocked`)를 보여 주는 것. Core에는 tab의 program 상태를 view에 주는 status가 없다. `core.activity`는 tab마다 활동 단계만 주고, program 상태를 담는 terminal status는 이 view에 거부된다. 대기: tab마다 program 상태를 view에 주는 core status(core가 아직 선언하지 않았다), 그리고 실행 중인 app에서 section의 window check.
- [~] A4 — P1: 에이전트 정의 section `agents.definitions`은 프로젝트의 group을 보여 주고, 사람이 빈 group을 만들게 한다. Group은 project data의 key `groups`에 있으며, `data`에 schema `object`, default `{}`로 선언한다. Core는 key의 값 전체를 저장하며, 값은 group 식별자마다 `{name, members}`를 담고 A5 전까지 `members`는 비어 있다. 명령 `agents.group.create {name}`은 `exposes`에 선언하며 `runtime.data.change`로 group을 더한다. Page `ui/definitions.html`과 `ui/definitions.js`는 group을 보여 주고 binder로 이름을 받는다. Group 규칙은 `ui/groups.js`에 있다(test 5개). 대기: 실행 중인 app에서 page의 window check. Group 안의 정의는 A5가 다룬다.
- [~] A5 — P1, core checklist의 F1063을 따른다: 정의는 group 하나에 속하는 role이다. `agents.definition.define {group, id, text, ko, files}`는 `files`에 절대 경로를 한 줄에 하나씩 받으며, group이 있고 식별자가 다른 group의 member가 아닌지 검사한 뒤 `core.role.define {id, text, ko, files}`을 실행하고, `runtime.data.change`로 식별자를 group의 members에 더한다. `agents.definition.remove {group, id}`는 `core.role.remove {id}`을 실행한 뒤 식별자를 group의 members에서 뺀다. Members는 식별자만 담는다. Page는 각 member의 text, ko, files를 status `core.roles`에서 읽으므로 지시 본문은 `roles.json`에만 있고, `core.roles`가 정의하지 않은 member는 정의되지 않음으로 보인다. Core의 거부는 그 문장으로 명령을 멈추며, members는 그대로 남는다. 규칙은 `ui/roles.js`에 있고 `test/roles.test.mjs`가 검사한다. `test/manifest-shape.test.mjs`는 두 명령을 검사한다. 남은 부분: 실행 중인 app에서 page의 window check.
- [~] A6 — P1, core checklist의 F1062를 따른다: 실행 중인 에이전트는 core의 owned session을 쓴다. 정의의 에이전트는 어떤 tab도 쥐지 않는 session에서 시작하고, tab은 요청할 때 그 session을 보여 준다. 진행: `ui/sessions.js`가 `core.session.open {plugin, params, size}`로 session을 시작하고(커맨드 `agents.session.start {plugin, params}`), `core.layout.open {card: "current", plugin, params: {session}}`로 열린 session을 보여 준다(커맨드 `agents.session.show {session}`). `core.sessions`가 나열하지 않는 session은 거부한다. running view가 두 커맨드를 연결하고 `core.sessions`를 관찰한다. 새 session의 크기는 view 크기와 기기 배율이다. 테스트 `test/sessions.test.mjs`(Red: 모듈이 없었다. Green: `node --test test/`가 42개 통과). 남은 것: (1) 정의의 에이전트를 시작하는 page가 아직 없다. 정의는 식별자만 담고, 계정이 보류(A2)이므로 plugin이나 program을 주는 출처가 없다. 대기: A2와 정의마다 program의 출처. (2) 보여 준 tab은 terminal plugin이 `sessions`를 선언하고 attach할 때만 붙는다. 그 전까지 core는 `plugin <id> declares no sessions`로 열기를 거부한다. 대기: terminal P210-2, P210-3과 `sessions`를 담은 core release. (3) 각 session의 소유자는 running section surface이며, 그 surface가 닫히면 session은 `owner-closed`로 끝난다(`docs/spec/plugins.md#owned-sessions`). 이는 section 수명의 제약이며 대기 항목이 아니다. (4) 어떤 tab도 보여 주지 않는 session을 running section의 행으로 나열하지 않는다. 이 단위는 커맨드만 추가했고, 행은 (2)가 window에서 검증된 뒤에 온다.
  - [!] A6-1 — P1, A6과 연결: 정의의 에이전트를 `agents.session.start`로 시작하는 트리거(page 또는 커맨드)다. 보류: 아무 page도 이 커맨드를 부르지 않는다. 원인: 정의는 식별자만 담고(A5), 에이전트 CLI를 가리키는 계정이 선언되지 않아(A2 보류) plugin이나 program을 주는 출처가 없다. 재개 조건: A2가 해결되어 정의가 member마다 plugin과 program을 담거나, 소유자가 program의 출처를 정할 때.
- [o] A7 — P1, A1의 후속: Manifest `plugin.json`은 `extends`에 extension point `makers`(point `agents.makers`)를 version `0.1.0`과 항목 schema로 선언한다. 항목 schema는 문자열이며 필수인 필드 `id`와 `name`이다. Maker plugin은 `contributes`의 항목으로 이 필드를 담아 group을 기여한다. Core F1064가 `sections`를 가진 plugin의 `extends`를 허용하므로 point에 surface가 필요 없다. `test/manifest-shape.test.mjs`가 이 선언을 검사한다. Core `validateManifest`는 core 원본에 대해 한 번 실행했을 때 manifest를 받아들인다. 이 repository의 test는 core를 읽지 않는다. F1064가 없는 core release는 `extends requires a surface`로 manifest를 거부하며, 그 release가 설치되기 전까지 그렇다.
- [o] A8 — P1, A7의 정정: `extends`의 point `makers` version은 `0.1.0`이 아니라 `0.0.1`이다. Plugin version은 0.0 계열을 유지하기 때문이다. `test/manifest-shape.test.mjs`가 이것을 검사한다. Red: version 검사가 기대값 `0.0.1`에 대해 `0.1.0`으로 실패했다. Green: 10개 test가 모두 통과한다.
