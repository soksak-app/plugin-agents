# 기능

항목 상태는 `[ ]` 대기, `[~]` 진행, `[o]` 완료, `[!]` 보류, `[-]` 종료다.
- [o] A1 — P1: Manifest `plugin.json`이 식별자 `agents`, 이름, 설명과 두 section `agents.running`, `agents.definitions`를 각각 page(A3, A4)를 가진 view section으로 선언한다. `test/manifest-shape.test.mjs`가 그 선언을 core plugin spec의 manifest 규칙과 대조한다.
- [!] A2 — P1: 에이전트 CLI 계정을 settings로 선언한다. 보류: 계정이 아직 settings로 선언되지 않았다. 원인: core plugin spec의 settings 선언은 setting마다 scalar 값 하나(enum, 정수 범위, 문자열, address)만 담고, 계정 목록을 담는 선언이 없다. 재개 조건: plugin 소유자가 계정을 core settings 형식으로 둘지, plugin의 project data(`data`)에 든 목록으로 둘지 정하면 이 항목을 재개한다.
- [!] A3 — P1: 실행 중인 에이전트 section `agents.running`은 에이전트 CLI를 실행하는 창의 terminal tab을 group, card, tab의 tree로 보여 준다. 각 행은 정의 이름, program 상태와 활동을 보여 주고, 행을 누르면 그 tab을 선택한다. 보류: plugin view가 watch할 수 있는 status가 창의 tab과 매개변수를 밝히지 않아서, 이 section은 agent tab과 shell tab을 구별할 수 없다. 원인: `core.layout`은 저장된 형태(core docs/spec/groups.ko.md, status와 query)이며 노드가 card와 box만 담고 tab은 없다. `core.grid`는 card마다 tab을 담지만 spec이 그 안의 tab 구성원을 밝히지 않는다. `core.card.get`은 tab마다 `{tab, plugin, status}`를 주며 매개변수가 없다. Tab 매개변수 `program`, `args`, `role`은 window snapshot(core docs/spec/exposure.ko.md, window snapshot)에만 있고, view는 그것을 보낼 수 없다. Terminal surface마다 있는 status는 `terminal.program`과 `terminal.activity`다. 재개 조건: core가 `core.grid` 또는 `core.card.get`의 tab 구성원에 `params`를 밝히거나, agent tab마다 program을 주는 status를 선언하면 이 항목을 재개한다.
- [~] A4 — P1: 에이전트 정의 section `agents.definitions`은 프로젝트의 group을 보여 주고, 사람이 빈 group을 만들게 한다. Group은 project data의 key `groups`에 있으며, `data`에 schema `object`, default `{}`로 선언한다. Core는 key의 값 전체를 저장하며, 값은 group 식별자마다 `{name, members}`를 담고 A5 전까지 `members`는 비어 있다. 명령 `agents.group.create {name}`은 `exposes`에 선언하며 `runtime.data.change`로 group을 더한다. Page `ui/definitions.html`과 `ui/definitions.js`는 group을 보여 주고 binder로 이름을 받는다. Group 규칙은 `ui/groups.js`에 있다(test 5개). 대기: core의 window check, 실행 중인 app에서 page를 판정한다. Group 안의 정의는 A5를 기다린다.
- [ ] A5 — P1, core checklist의 F1063을 따른다: 정의는 role 명령 `core.role.define`과 `core.role.remove`를 쓰고 status `core.roles`를 읽어서, 정의의 지시 본문이 `roles.json`에만 있게 한다. 대기: core F1063-2.
- [ ] A6 — P1, core checklist의 F1062를 따른다: 실행 중인 에이전트는 core의 owned session을 쓴다. 정의의 에이전트는 어떤 tab도 쥐지 않는 session에서 시작하고, tab은 요청할 때 그 session을 보여 준다. 대기: core F1062-3.
- [o] A7 — P1, A1의 후속: Manifest `plugin.json`은 `extends`에 extension point `makers`(point `agents.makers`)를 version `0.1.0`과 항목 schema로 선언한다. 항목 schema는 문자열이며 필수인 필드 `id`와 `name`이다. Maker plugin은 `contributes`의 항목으로 이 필드를 담아 group을 기여한다. Core F1064가 `sections`를 가진 plugin의 `extends`를 허용하므로 point에 surface가 필요 없다. `test/manifest-shape.test.mjs`가 이 선언을 검사한다. Core `validateManifest`는 core 원본에 대해 한 번 실행했을 때 manifest를 받아들인다. 이 repository의 test는 core를 읽지 않는다. F1064가 없는 core release는 `extends requires a surface`로 manifest를 거부하며, 그 release가 설치되기 전까지 그렇다.
- [o] A8 — P1, A7의 정정: `extends`의 point `makers` version은 `0.1.0`이 아니라 `0.0.1`이다. Plugin version은 0.0 계열을 유지하기 때문이다. `test/manifest-shape.test.mjs`가 이것을 검사한다. Red: version 검사가 기대값 `0.0.1`에 대해 `0.1.0`으로 실패했다. Green: 10개 test가 모두 통과한다.
- [o] A9 — P1, A7의 후속: Extension point `agents.makers`의 interface는 `docs/spec/makers.ko.md`에 정의한다. 기여된 module은 `group()`을 export하고, 이것은 필수 member `id`, `name`, `plugin`, `clis`, `agents`(각각 `name`, `path`, `cli`와 선택 `port`, `model`을 가짐), `skills`, `variables`, `path`, `folders`, `rules`를 가진 group object를 돌려준다. Provider는 연결된 항목마다 `group()`을 호출한다. `test/maker-interface.test.mjs`가 spec의 group schema를 sample group과, `plugin.json`의 항목 schema를 검사한다. Red: spec 파일이 없을 때 test가 실패했다. Green: 4개 test가 모두 통과한다.
