# Features

Cause: the settings declarations of the core plugin specification hold one scalar value per setting (an enum, a bounded integer, a string or an address), and no declaration holds a list of accounts. - [~] A3 — P1: The running agents section `agents.running` lists the agent tabs of the window as the group, card and tab tree of `core.grid`: a tab of any plugin whose `params.program` is set, named by `params.role` or else `params.program`, with the activity of each tab from `core.activity`. The page is `ui/running.html` with `ui/running-view.js`. Remaining: the program detail of each row (`idle`, `working`, `blocked`). No core status gives a view the program state of a tab: `core.activity` gives only the activity level of each tab, and the terminal statuses that hold the program state are refused to this view. Waits for: a core status that gives a view the program state of each tab, which core does not declare, and the window check of the section in the running app.
- [~] A4 — P1: The agent definitions section `agents.definitions` shows the groups of the project and lets a person create an empty group. The groups are project data under the key `groups`, declared in `data` with the schema `object` and the default `{}`; core stores the whole value of the key, which holds each group identifier with `{name, members}` and an empty `members` until A5. The command `agents.group.create {name}`, declared in `exposes`, adds the group with `runtime.data.change`; the page `ui/definitions.html` with `ui/definitions.js` lists the groups and enters the name through the binder. The group rules are in `ui/groups.js` (5 tests). Waits for: the window check of the page in the running app. Definitions in a group are A5.
- [~] A5 — P1, follows F1063 of the core checklist: A definition is a role that belongs to one group. `agents.definition.define {group, id, text, ko, files}`, where `files` holds one absolute path per line, checks that the group exists and that the identifier is not a member of another group, runs `core.role.define {id, text, ko, files}`, and then adds the identifier to the members of the group with `runtime.data.change`. `agents.definition.remove {group, id}` runs `core.role.remove {id}` and then removes the identifier from the members of the group. The members hold identifiers only: the page reads the text, the Korean text and the files of each member from the status `core.roles`, so the instruction text lives only in `roles.json`, and a member that `core.roles` does not define is shown as not defined. A refusal of core stops the command with its text, and the members stay as they were. The rules are in `ui/roles.js`, and `test/roles.test.mjs` checks them; `test/manifest-shape.test.mjs` checks the two commands. Remaining: the window check of the page in the running app.
- [~] A6 — P1, follows F1062 of the core checklist: The running agents use owned sessions of core: a definition's agent starts in a session that no tab holds, and a tab shows it on request. The running view wires both commands and watches `core.sessions`; the size of a new session is the view size and the device scale.
