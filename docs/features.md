# Features

Items use the states `[ ]` waiting, `[~]` active, `[o]` complete, `[!]` held and `[-]` closed.
- [o] A1 — P1: The manifest `plugin.json` declares the identifier `agents`, the name, the description and the two sections `agents.running` and `agents.definitions` as view sections with their pages (A3 and A4). `test/manifest-shape.test.mjs` checks the declaration against the manifest rules of the core plugin specification.
- [!] A2 — P1: The accounts of the agent CLIs are declared as settings. Held: the accounts are not declared as a setting yet. Cause: the settings declarations of the core plugin specification hold one scalar value per setting (an enum, a bounded integer, a string or an address), and no declaration holds a list of accounts. Retry when: the owner of the plugin decides whether accounts are a core settings type or a list in the project data of the plugin (`data`), which resumes this item.
- [~] A3 — P1: The running agents section `agents.running` lists the agent tabs of the window as the group, card and tab tree of `core.grid` (the tabs with `params.program`, the terminal plugin), named by `params.role` or else `params.program`, with the activity of each tab from `core.activity`. A press runs `agents.running.select {tab}`, which runs `core.layout.select`. The tree rules are in `ui/running.js` (3 tests); the page is `ui/running.html` with `ui/running-view.js`. Row state is the tab activity only: a view may watch only core statuses and the statuses of its own plugin, so the terminal statuses `terminal.program` and `terminal.activity` are refused to this view. Needs the next core release that contains F1068 (`core.grid` tabs with `params`); a core without it fails the tree with a missing `params`. Waits for: the window check of the section in the running app.
- [~] A4 — P1: The agent definitions section `agents.definitions` shows the groups of the project and lets a person create an empty group. The groups are project data under the key `groups`, declared in `data` with the schema `object` and the default `{}`; core stores the whole value of the key, which holds each group identifier with `{name, members}` and an empty `members` until A5. The command `agents.group.create {name}`, declared in `exposes`, adds the group with `runtime.data.change`; the page `ui/definitions.html` with `ui/definitions.js` lists the groups and enters the name through the binder. The group rules are in `ui/groups.js` (5 tests). Waits for: the window check of the page in the running app. Definitions in a group wait for A5.
- [ ] A5 — P1, follows F1063 of the core checklist: The definitions use the role commands `core.role.define` and `core.role.remove` and read the status `core.roles`, so the instruction text of a definition lives only in `roles.json`. Waits for core F1063-2.
- [ ] A6 — P1, follows F1062 of the core checklist: The running agents use owned sessions of core: a definition's agent starts in a session that no tab holds, and a tab shows it on request. Waits for core F1062-3.
