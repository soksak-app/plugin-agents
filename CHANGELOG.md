# Changelog

[한국어](CHANGELOG.ko.md)

- A1: The repository holds the manifest `plugin.json` with the identifier `agents`, the name, the description and the sections `agents.running` and `agents.definitions`, whose pages `ui/running.html` and `ui/definitions.html` are empty documents until A3 and A4. `test/manifest-shape.test.mjs` checks the declaration, and `test/install.test.mjs` and `test/test-script.test.mjs` check the Makefile and the test command. The version is 0.0.0 and is not released.
- A7: The manifest `plugin.json` declares the extension point `makers` in `extends` with version `0.1.0` and an item schema of the required string fields `id` and `name`. `test/manifest-shape.test.mjs` checks the declaration. Red: `plugin.json declares the extension point agents.makers in extends with its version and schema` failed with `extends` undefined. Green: all 10 tests of `node --test test/` pass, and core `validateManifest` accepts the manifest when run once against the core source.
- A8: The version of the point `makers` in `extends` is `0.0.1`, because the plugin versions stay in the 0.0 series. Red: the version assertion of `test/manifest-shape.test.mjs` failed with `0.1.0`. Green: all 10 tests of `node --test test/` pass, and core `validateManifest` accepts the manifest.
- A9: The interface of the extension point `agents.makers` is defined in `docs/spec/makers.md`: the contributed module exports `group()`, which returns the group object with its required members and the optional `port` and `model` of each agent. `test/maker-interface.test.mjs` checks the spec schema against a sample group. Red: the test failed without the spec. Green: all 4 tests pass.
- A4 (declaration): The repository declares the project data key `groups` in `data` with the schema `object` and the default `{}`, which holds the groups of the definitions section; the page and the create command follow. Red: `plugin.json declares the project data key groups, an object whose default is empty` failed with `data` undefined. Green: all 15 tests of `node --test test/` pass, and core `validateManifest` accepts the manifest.
- A3 (held): Section `agents.running` waits for a core status of the window layout; the view cannot read the tree today. The status of the program and the activity of each terminal surface and `core.activity` exist. No page code is added.
- A4: The definitions section lists the groups of the project from the key `groups` and creates an empty group through the command `agents.group.create`, which the page enters through the binder and which adds the group with `runtime.data.change`. `ui/groups.js` holds the group rules, and `test/groups.test.mjs` checks them. The manifest test checks the `data` and `exposes` declarations. Red: `test/groups.test.mjs` failed without the module, and the manifest tests failed for the command with `exposes` undefined. Green: all 21 tests of `node --test test/` pass, and core `validateManifest` accepts the manifest. The window check of the page is not run here.
- A3 (held): the cause is corrected: no status that a view can watch states the parameters of a tab, so the section cannot identify agent tabs. See the held item in `docs/features.md`.
- A3: The running agents section draws the agent tabs of the window from `core.grid` as a group, card and tab tree, with the activity of each tab from `core.activity`; a press runs `agents.running.select`, which runs `core.layout.select`. The tree rules are in `ui/running.js`, and `test/running.test.mjs` checks them. The manifest test checks the second command. Red: `test/running.test.mjs` failed without the module, and the manifest test failed with the select command missing. Green: all 24 tests of `node --test test/` pass, and core `validateManifest` accepts the manifest. The state is the tab activity only, because a view cannot watch the terminal statuses. The section needs the next core release with F1068. The window check is not run here.
- A11: The agent tab rule names no plugin: a tab of any plugin whose `params.program` is set is an agent tab. Red: the other-plugin tab with `params.program` was left out, and the expected tree failed. Green: all 25 tests of `node --test test/` pass.
- A5: The definitions section defines and removes roles in groups. `agents.definition.define` runs `core.role.define` and then adds the identifier to the members of the group, and `agents.definition.remove` runs `core.role.remove` and then removes it. The page draws each member with its text from the status `core.roles`. `ui/roles.js` holds the rules, `test/roles.test.mjs` checks them and the manifest test checks the two commands. Red: `test/roles.test.mjs` failed without the module, and the manifest test failed with the commands missing. Green: all 34 tests of `node --test test/` pass. The window check of the page is not run here.
- A6: The running agents section declares the commands `agents.session.start {plugin, params}`, which opens an owned session with `core.session.open {plugin, params, size}`, and `agents.session.show {session}`, which opens a tab on an open session with `core.layout.open {params: {session}}` (`ui/sessions.js`, `test/sessions.test.mjs`). No page starts a session yet, and the shown tab attaches only after the terminal plugin declares `sessions` (A6 stays open).
